# @abikmukhametov/dsh-personal-memory

Пакет добавляет два раздела памяти: «О пользователе» и «Об агенте». Агент может прочитать записи и по явной просьбе в чате добавить, изменить или удалить запись инструментами `memory_list`, `memory_add`, `memory_edit`, `memory_delete`. В Settings → Memory записи можно просмотреть, добавить, изменить и удалить вручную. Изменения через интерфейс и инструменты используют одно хранилище.

Память общая для всех профилей и всех пользователей одного Host с одним `DSH_HOME`; разграничения записей по учётной записи нет. На общем сервере каждый пользователь Web-интерфейса может видеть и менять эти записи. Перед следующим запросом модели пакет добавляет в журнал и контекст диалога snapshot всех сохранённых записей. При неизменной памяти повторной записи нет; после изменения видимый snapshot заменяется, а после compaction добавляется заново. Уже использованные факты могут остаться в истории или summary открытого диалога после удаления записи либо выключения пакета.

## Установка

Пакет рассчитан на DSH `0.2.0-rc.2` и использует уже подготовленный официальный checkout с зависимостями и сборкой; подготовка среды описана в [корневом README](../../README.md#подготовка-среды). Из корня каталога плагинов:

```powershell
$env:DSH_SOURCE_ROOT = 'D:\path\to\deepseek-harness'
node plugins/personal-memory/scripts/pack.mjs
```

Задайте `DSH_HOME` как абсолютный путь к профилю нужного Host. Из корня checkout DSH установите готовый архив:

```powershell
$env:DSH_HOME = 'D:\path\to\dsh-home'
pnpm dsh plugin --profile web add 'D:\path\to\dsh-plugins-public\plugins\personal-memory\artifacts\abikmukhametov-dsh-personal-memory-0.1.1.tgz'
```

Перезапустите Web. Удаление: `pnpm dsh plugin --profile web remove @abikmukhametov/dsh-personal-memory` из того же checkout DSH с тем же `DSH_HOME`.

## Хранение и пределы

JSON domain `personal_memory` находится в `DSH_HOME/storages/personal_memory.json`; схема версии 1 сохраняет записи, идентификаторы, даты и revision. Пределы: до 10 записей в каждом разделе, до 2000 символов на запись и до 24000 символов на полный snapshot вместе с метаданными. Добавление или правка, которая превысит предел, отклоняется без изменения сохранённых данных. Автоматического вытеснения нет.

Пока пакет включён, `DSH_HOME/storages/personal_memory.lock` удерживает единственный Host-писатель. Второй Host с тем же домом получает ошибку включения. При штатной остановке Host снимает свою блокировку; после аварийного завершения файл может остаться. Повреждённый JSON domain отклоняется; пакет его не сбрасывает.

### Если память не включается

Сообщение `another Host owns ... personal_memory.lock` означает, что файл блокировки уже существует. Остановите все Host с этим `DSH_HOME`: в окне запуска нажмите Ctrl+C и дождитесь завершения процесса. Если плагин не включился из-за старого файла, остановка нового Host этот файл не удалит, поскольку он не владел блокировкой. Убедившись, что другой Host с тем же `DSH_HOME` не работает, удалите только файл блокировки в PowerShell и запустите Web снова:

```powershell
Remove-Item -LiteralPath (Join-Path $env:DSH_HOME 'storages/personal_memory.lock')
```

Файл `DSH_HOME/storages/personal_memory.json` содержит записи памяти; при восстановлении блокировки его не удаляют.

Изменяющие инструменты агента проверяют действующий sandbox mode и при необходимости запрашивают одноразовое разрешение через штатный approval. Отказ и отмена не меняют память. Ручные действия в авторизованном Web-интерфейсе используют Host RPC и не требуют согласования инструмента агента. Данные памяти передаются модели как данные, а не как инструкция. Автоматический импорт памяти `pet_agent` не выполняется.
