# Правила репозитория

Этот репозиторий готовится к публикации. В него входят четыре плагина, их тесты и скрипты сборки, документация по установке, лицензия и материалы переводов с указанием источника.

## Публикуемые данные

- Считайте потенциально публичными каждый коммит, файл, сообщение коммита, данные автора, Git ref, созданный архив и журнал GitHub. `.gitignore` не защищает данные, уже попавшие в коммит.
- Имя автора `Айдар Бикмухаметов` и адрес `ARBikmuhametov@yandex.ru` разрешены к публикации. Это исключение не относится к другим контактным данным или личным рабочим материалам.
- Не публикуйте credentials, данные сессий и профиля, личные заметки, пути локального компьютера, сведения о работодателе и клиентах, внутренние проекты и материалы с неподтверждённым публичным статусом. Не выводите значения возможных секретов в журналы проверки.
- Если происхождение находки неясно, остановите push или изменение публичности. Удалите нежелательный файл из каждого отправляемого коммита, а не только из последней версии, затем повторите проверку.

## Проверка перед отправкой

1. Сверьте точные адрес, ветку и refspec через `git remote -v`, `git status --short --branch` и `git ls-remote --heads --tags origin`. Не применяйте `--all`, `--mirror` и `--tags` при обычном push.
2. Для нового репозитория запустите `node scripts/check-publication.mjs --all`. Перед следующими push обновите сведения об удалённой ветке и запустите `node scripts/check-publication.mjs --range <remote-ref>..HEAD` для всего отправляемого диапазона. Каждую отправляемую ветку или тег проверяйте отдельно.
3. Вручную просмотрите полный список файлов и diff отправляемых коммитов. Проверяйте документацию, примеры, заимствованные файлы и двоичные или сгенерированные материалы так же внимательно, как исходный код. Подтвердите публичность каждого элемента: сканер находит только известные признаки.
4. Перед изменением публичности проверьте материалы GitHub: запуски и артефакты Actions, релизы, issues и pull requests. Успешная локальная проверка не охватывает эти поверхности.
5. Зафиксируйте результат проверки и точный коммит. Отправляйте изменения только после устранения всех находок. Если коммит изменился, повторите проверку.
